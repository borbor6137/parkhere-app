# ตารางยอดเงินอ้างอิง (golden) ของ ParkHere

ใช้ยืนยันว่ายอดเงินไม่เปลี่ยนเมื่อรวมสูตรเป็นฟังก์ชันเดียว (งาน P1) และในทุกรอบ QA ต้องมี Node 18+ ไม่ต้องติดตั้งแพ็กเกจ

## รัน

```
node tests/pricing/check-golden.js
```

ผลที่ถูกต้อง: `ผ่าน: 14677 เซลล์ตรงกับ golden.json ...` (รหัสออก 0) ถ้าไม่ตรง จะพิมพ์เซลล์ที่ผิดและออกด้วยรหัส 1

## ไฟล์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `golden.json` | ค่าอ้างอิง 8 ชุด config × นาที 0-600 ทีละ 1 นาที (ราคา `price`, ค่าจอดตอนออกจริง `fee`, ค่านับสด `live`) + นาทีมาก ๆ + ขอบมิลลิวินาที ชุดที่โจทย์กำหนดคือ A (rate 20/ฟรี 30), B (15/0), C (37/45) ที่เหลือเป็นกรณีขอบ (rate 0, ไม่มี config, ค่าเป็นสตริง ฯลฯ) |
| `adapter-current.js` | ดึงสูตรฝั่งผู้ใช้จาก `script.js` ด้วย regex แล้วรันใน `vm` (price, parkMin, ค่าประมาณก่อนยืนยันออก, นาฬิกานับสด 3 จุด, การอ่าน config) และมี `guards()` เฝ้า `admin.html`/`master.html`/`admin-core.js` ว่าไม่มีสูตรราคา และยังแสดง `b.amt`/`b.park` จากเซิร์ฟเวอร์ (หน้าจอและ CSV) ถ้าโค้ดถูกแก้จนหาสูตรไม่เจอ จะ throw พร้อมบอกว่าหาอะไรไม่เจอ |
| `check-golden.js` | เทียบ adapter กับ `golden.json` ทุกเซลล์ |
| `gen-golden.js` | สร้าง `golden.json` จากสูตรผู้ใช้ปัจจุบัน และไขว้กับ `pricing.js` (api) จะไม่เขียนไฟล์ถ้าสองฝั่งให้ค่าไม่ตรงกัน (ห้ามรันเพื่อให้ผ่าน) |

## สถานะหลัง M3/M5 (ยอดเงินคิดที่ pricing.js ที่เดียว)

- ยอดจริง (ค่าจอง, ค่าจอดตอนออก) คิดที่ `thingsboard/api/pricing.js` ฟังก์ชันเดียว พิสูจน์ด้วย golden ตารางเดียวกัน: `node tests/pricing/check-golden.js thingsboard/api/test/adapter-pricing.js` (14664 เซลล์) ต้องผ่านทุกครั้งคู่กับคำสั่งปกติ
- admin/master ไม่คำนวณยอดเอง (M5) แสดงเฉพาะ `amt`/`park` ที่ API ส่งมา ดังนั้น golden เทียบ "สูตรในหน้า admin" ไม่ได้อีก (ไม่มีสูตรให้เทียบ) แทนด้วย guards: ถ้ามีคนเพิ่มสูตรราคากลับเข้ามาในหน้า admin จะไม่ผ่าน
- ที่ golden ยังครอบคลุม: สูตร pricing.js ทุกเซลล์, สูตรประมาณ/นาฬิกานับสดใน script.js (แสดงผลเท่านั้น ไม่ใช่ยอดจริง) ตรงกับ golden เดียวกัน
- ที่ไม่ครอบคลุม: ค่าที่ admin แสดงตรงกับที่ API ส่งจริงหรือไม่ในเบราว์เซอร์ (ครอบด้วยเทสต์ API/เบราว์เซอร์ของ M5) และค่า config ที่ผิดช่วง
- ห้ามสร้าง `golden.json` ใหม่เพื่อให้ผ่าน ถ้ายอดเปลี่ยนคือบั๊ก หรือเป็นการตัดสินใจของเจ้าของที่ต้องบันทึกเหตุผล
- หมายเหตุ: `meta.source` ใน golden.json ยังอ้างเลขบรรทัดของ admin.html/master.html แบบเก่า (เอกสารประวัติ ไม่กระทบเซลล์)

## สิ่งที่ golden จับได้ว่าสามไฟล์ทำงานต่างกัน (known quirks)

อยู่ใน `golden.json` ที่ `meta.knownQuirks` เช่น นาฬิกานับสดไม่มีขั้นต่ำ 1 นาที (live[0] ต่างจาก fee[0] เมื่อฟรี 0 นาที), `rate = 0` ถูกตีเป็น 20, ต้องคงรูปนิพจน์ `Math.ceil(m/60*rate)` เพราะ `Math.ceil(m*rate/60)` ให้ผลต่างกัน 31 จาก 4808 เซลล์
